Machine learning model development

A "model" is just a math formula with knobs (called parameters) that the computer turns by itself until its guesses stop being wrong.

imagine this

You're guessing how much a pizza costs from its size. At first you guess wildly. Each time you're wrong, you nudge your guess a little closer to the real price. Do that thousands of times with thousands of pizzas, and you get shockingly good at guessing. That nudging process is machine learning.

The 6 steps every model goes through

  1. Collect data. Gather real examples — photos, prices, sensor readings. Bad or too little data means a model that guesses badly no matter how clever the math is.
  2. Clean it. Fix missing values, remove duplicates, and put everything in the same format. Real-world data is messy — this step often takes longer than any other.
  3. Split it. Divide data into a training pile (to learn from) and a test pile (to honestly check itself against, like a pop quiz on questions it hasn't seen).
  4. Train. The model makes a guess, measures how wrong it was (the loss), and adjusts its knobs slightly to be less wrong next time. Repeat thousands of times.
  5. Evaluate. Test on the unseen pile. If it did great on training but poorly on the test, it memorized instead of learning — this is called overfitting.
  6. Deploy & monitor. Ship it into a real app, then keep watching it — the real world changes, and yesterday's good model can quietly get worse (see MLOps).

Try it yourself: teach a line to fit the dots

A model predicts price = weight × size + bias. Drag the two sliders — you're doing manually what training does automatically: nudging knobs to shrink the error.

Total error: -

error = sum of (real price − predicted price)² for every dot — lower is better. Real training finds the lowest point automatically using an algorithm called gradient descent; you're doing it by hand.

What this looks like as real code

Here's the same idea — a line learning to fit data — written with a popular ML library called scikit-learn. It does the slider-nudging for you.

train_price_model.py
# 1. Get the data ready: size (sq. ft) and price ($1000s)
import numpy as np
from sklearn.model_selection import train_test_split
from sklearn.linear_model import LinearRegression

sizes  = np.array([[650],[800],[1200],[1500],[2100]])
prices = np.array([70, 90, 145, 180, 250])

# 2. Split: 80% to learn from, 20% to honestly test on
X_train, X_test, y_train, y_test = train_test_split(
    sizes, prices, test_size=0.2, random_state=42
)

# 3. Train: the model tunes its own weight and bias
model = LinearRegression()
model.fit(X_train, y_train)

# 4. Evaluate on data it has never seen
score = model.score(X_test, y_test)
print(f"How well it explains prices: {score:.2f}")

# 5. Use it to predict a brand-new house
guess = model.predict([[1000]])
print(f"A 1000 sq.ft house should cost about ${guess[0]:.0f}k")
Why split the data at all?

If you tested a model on the same questions it studied, it could just memorize the answer sheet. Testing on unseen data proves it actually learned the pattern, not the specific answers.

Quick check

Explanation: high training score + low test score is the classic sign of memorizing answers instead of learning the underlying pattern.

Machine learning algorithms

A "model" needs a recipe for how it learns — that recipe is the algorithm. Different algorithms are just different strategies for finding patterns, each suited to different kinds of problems.

imagine this

If "machine learning" is the goal of getting good at a task through practice, an algorithm is the specific study method: flashcards, drawing diagrams, asking a friend, grouping similar notes together. Different methods work better for different subjects — same with ML algorithms and different problems.

The 3 kinds of learning

TypeWhat it getsWhat it learnsExample
SupervisedExamples with the correct answer attachedTo predict the answer for new, unlabeled examplesGiven house sizes and prices, predict a new house's price
UnsupervisedExamples with no answers at allTo find hidden structure or groupings on its ownGroup customers into segments by shopping behavior
ReinforcementA score (reward) after taking actionsTo choose actions that earn the most reward over timeAn agent learning to play a game by trial and error

Common algorithms, in plain words

Linear & logistic regression

Draws the best straight line (or curve) through data. Linear predicts a number; logistic predicts a yes/no probability.

Decision trees

Asks a series of yes/no questions, like a flowchart, until it reaches an answer.

Random forest

Grows many different decision trees and lets them vote — a "wisdom of the crowd" for predictions.

K-Nearest Neighbors (KNN)

Classifies a new point by looking at whichever labeled points are closest to it.

Support Vector Machine (SVM)

Finds the widest possible gap between two groups and draws the boundary right down the middle.

Naive Bayes

Uses probability — "given these clues, which answer was historically most likely?" Fast and great for text/spam filtering.

K-Means clustering

Unsupervised — automatically groups similar points into K clusters with no labels needed.

Gradient boosting (XGBoost)

Builds trees one at a time, each one fixing the mistakes of the last — a favorite for tabular data competitions.

Reaches a final split of yes/no branches.

The code: three algorithms, three lines each

Thanks to scikit-learn, swapping algorithms is often just swapping one line — the surrounding fit/predict pattern stays the same.

try_algorithms.py
from sklearn.neighbors import KNeighborsClassifier
from sklearn.tree import DecisionTreeClassifier
from sklearn.ensemble import RandomForestClassifier

# Same data, same fit/predict pattern — only the algorithm changes
models = {
    "KNN":           KNeighborsClassifier(n_neighbors=3),
    "Decision Tree":  DecisionTreeClassifier(max_depth=4),
    "Random Forest": RandomForestClassifier(n_estimators=100),
}

for name, model in models.items():
    model.fit(X_train, y_train)
    accuracy = model.score(X_test, y_test)
    print(f"{name}: {accuracy:.1%} accurate")

# Unsupervised example: group customers with no labels at all
from sklearn.cluster import KMeans
groups = KMeans(n_clusters=3).fit_predict(customer_data)
So which one do I pick?

There's no single best algorithm for every problem — this is called the "no free lunch" idea. Engineers usually try a few fast, simple algorithms first (like logistic regression or a decision tree) as a baseline, before reaching for slower, more powerful ones like deep neural networks (see the Deep Learning lesson).

Not all data needs deep learning

For structured, spreadsheet-style data (rows and columns of numbers), tree-based methods like random forest or gradient boosting often beat neural networks — and train in seconds, not hours. Deep learning tends to shine specifically on images, audio, and text.

Deep learning

Deep learning is machine learning built from layers of tiny decision-makers called neurons, stacked deep — hence the name.

imagine this

Think of an office where a question passes through several desks. Desk 1 does a small calculation and passes its answer to Desk 2. Desk 2 tweaks it and passes it to Desk 3. By the last desk, a simple question ("is this a cat?") has been refined through hundreds of small decisions into one confident answer. Each "desk" is a layer of neurons.

What one neuron actually does

A neuron takes numbers in, multiplies each by a learned weight (how important that input is), adds a bias, and passes the result through a squashing function called an activation that decides how strongly to "fire".

Try it yourself: fire a neuron

This neuron looks at two clues about an email — how spammy the words sound and how many links it has — and decides "spam" or "not spam".

Neuron says: —

score = (words × 0.7) + (links × 1.1) − 4 → activation turns it into a 0–1 "confidence"

Why "deep"? Stacking layers

One neuron can only draw a simple boundary. Stack thousands of them into layers, and the network builds up understanding step by step — this is exactly what happens inside a Convolutional Neural Network (see the CNN lesson) when it looks at a photo.

Input layer

Raw numbers go in — pixel brightness, word scores, sensor readings.

Hidden layer 1

Learns tiny patterns — edges, simple combinations.

Hidden layer 2

Combines those into bigger patterns — shapes, phrases.

Hidden layer 3

Combines further — objects, meaning, intent.

Output layer

Turns everything into a final answer — "cat", "spam", "0.92".

The code: a tiny neural network

Here's a real, working 3-layer network built with Keras (you'll meet it properly in the Keras lesson) that learns the classic XOR pattern — a problem too curved for a single straight line to solve, which is exactly why we need layers.

tiny_network.py
import numpy as np
from tensorflow import keras
from tensorflow.keras import layers

# Inputs (two switches) and the correct answers (XOR: "exactly one is on")
X = np.array([[0,0], [0,1], [1,0], [1,1]])
y = np.array([0, 1, 1, 0])

model = keras.Sequential([
    layers.Dense(8, activation="relu",    input_shape=(2,)),  # hidden layer
    layers.Dense(1, activation="sigmoid"),                     # output: 0 to 1
])

model.compile(optimizer="adam", loss="binary_crossentropy", metrics=["accuracy"])
model.fit(X, y, epochs=300, verbose=0)

print(model.predict(X).round(2))  # close to [0, 1, 1, 0]
Word check

Epoch = one full pass through all the training data. Loss = a number that measures how wrong the network is; training's whole job is shrinking it.

Model training & production deployment

Training happens in a lab, on powerful machines, with time to spare. Deployment means putting the finished model where real people actually use it — and real users don't wait.

imagine this

Training is a chef perfecting a recipe in a test kitchen, tasting and adjusting for weeks. Deployment is opening the restaurant: the recipe is locked in, and now it has to come out fast, correctly, and for hundreds of customers a minute — every single night.

Training loop, in plain steps

  1. Forward pass. Feed a batch of examples in and get predictions out.
  2. Measure loss. Compare predictions to the real answers with a loss function.
  3. Backward pass (backpropagation). Work out which knob, turned which way, would have reduced the loss.
  4. Update weights. An optimizer (like Adam or SGD) nudges every knob a tiny step in that direction.
  5. Repeat for every batch, for many epochs, until loss stops improving.

Try it yourself: watch loss fall during training

This is what an engineer stares at for hours. Press play — loss should trend down and accuracy up as fake "epochs" pass.

Getting a trained model into production

1. Save it

Export the trained weights to a portable file — Keras uses .keras/.h5, PyTorch uses .pt, others use the open ONNX format.

2. Wrap it

Put the model behind an API, usually with a small web server, so any app can send data and get a prediction back.

3. Containerize

Package the model, server, and dependencies into a Docker container so it runs identically everywhere.

4. Serve at scale

Run many containers behind a load balancer so thousands of requests a second get fast answers.

The code: a minimal serving API

This tiny web server loads a saved model once, then answers prediction requests — the actual bridge between "trained model" and "real product".

serve_model.py
from fastapi import FastAPI
import tensorflow as tf
import numpy as np

app = FastAPI()
model = tf.keras.models.load_model("models/spam_detector.keras")  # load once, at startup

@app.post("/predict")
def predict(spammy_words: float, links: float):
    features = np.array([[spammy_words, links]])
    score = float(model.predict(features)[0][0])
    return {"is_spam": score > 0.5, "confidence": round(score, 3)}

# Run with: uvicorn serve_model:app --host 0.0.0.0 --port 8000
# Now any app on Earth can POST to /predict and get an answer in milliseconds
The gap engineers fear most

A model that's 99% accurate in the lab can fail in production if live data looks different from training data — blurrier photos, a new slang word, a camera angle nobody trained on. This is why deployment always comes with monitoring (see the MLOps lesson).

Model optimization

A model trained on a huge lab computer can be too big, slow, or power-hungry for a phone, a doorbell camera, or a tiny sensor. Optimization shrinks and speeds up a model without losing much of its smartness.

imagine this

Imagine a 500-page textbook. A skilled student can turn it into a 20-page revision guide that still covers 95% of what matters, in a fraction of the reading time. Model optimization is writing that revision guide — for a neural network.

The main techniques

TechniqueWhat it doesIn plain words
QuantizationStores numbers using fewer bits (e.g. 8-bit instead of 32-bit)Rounding every measurement to the nearest inch instead of the nearest millimeter — still useful, way lighter
PruningRemoves weights that barely affect the outputCutting the dead branches off a tree — the tree still stands, just leaner
Knowledge distillationTrains a small "student" model to mimic a big "teacher" modelA senior expert teaches a quick summary to a junior, who then performs almost as well
Compilation / graph optimizationFuses and reorders operations for the target hardwareRewriting a recipe's steps so the kitchen never sits idle between tasks

The code: quantizing a model

This converts a full-size trained model into a compressed TFLite version ready for a phone or a small edge device — the same technique that keeps a camera's on-device AI fast.

optimize_model.py
import tensorflow as tf

model = tf.keras.models.load_model("models/detector.keras")

converter = tf.lite.TFLiteConverter.from_keras_model(model)
converter.optimizations = [tf.lite.Optimize.DEFAULT]   # turns on quantization

tiny_model = converter.convert()

with open("detector_quantized.tflite", "wb") as f:
    f.write(tiny_model)

# Result: often 4x smaller and 2-3x faster, for roughly 1-2% less accuracy
Why this matters for cameras and drones

An edge AI camera can't send every video frame to a giant cloud server — that's slow and expensive. A optimized model running directly on the camera can spot a person or a vehicle in milliseconds, which is exactly what platforms like Scanalitix rely on at the edge.

Foundations › Lesson 7 of 15

MLOps

MLOps ("Machine Learning Operations") is the set of habits and tools that keep a model working well after it launches — not just on launch day.

imagine this

Getting a car through its driving test is training. MLOps is everything after: regular services, checking the tires, noticing when the engine sounds different, and knowing when it's time for a new car. Without this, even a great model quietly gets worse as the real world changes around it — a problem called drift.

The MLOps loop

Version

Track exactly which data and code produced which model, so results are reproducible.

Deploy

Roll the model out safely, often to a small slice of traffic first.

Monitor

Watch accuracy, latency, and incoming data for warning signs, 24/7.

Detect drift

Notice when live data starts looking different from training data.

Retrain

Feed fresh, labeled examples back in and ship an improved model — then repeat.

Try it yourself: spot the drift

A model was trained on daytime traffic footage. Toggle "night mode" and watch what happens to live accuracy — this is exactly the kind of silent drop MLOps monitoring is built to catch.

A monitoring system would fire an alert once accuracy drops below its threshold, triggering a retraining job automatically.

The code: a simple drift check

A real MLOps pipeline runs a check like this automatically, every day, on a schedule.

check_drift.py
import numpy as np

def accuracy_dropped(recent_accuracy, baseline_accuracy, threshold=0.03):
    """Return True if live accuracy has fallen too far below the launch baseline."""
    drop = baseline_accuracy - recent_accuracy
    return drop > threshold

# pulled from yesterday's monitoring logs
baseline = 0.97       # accuracy on launch day
today     = 0.91      # accuracy measured on today's live traffic

if accuracy_dropped(today, baseline):
    print("⚠️  Drift detected — queuing a retraining job and alerting the ML team")
else:
    print("✅ Model healthy")
Word check

Drift = the world changing so live data no longer matches training data. CI/CD for ML = automatically testing and deploying new model versions the same way software teams automatically test and deploy code.

OpenCV

To a computer, a photo is just a giant grid of numbers. OpenCV is a free toolbox full of ready-made functions for working with those numbers — blurring, finding edges, detecting faces, reading video frames.

imagine this

The code: face detection in a few lines

detect_faces.py
import cv2

# Load a ready-made face detector that ships with OpenCV
face_finder = cv2.CascadeClassifier(cv2.data.haarcascades + "haarcascade_frontalface_default.xml")

frame = cv2.imread("entrance_camera.jpg")
gray  = cv2.cvtColor(frame, cv2.COLOR_BGR2GRAY)     # color isn't needed for this step

faces = face_finder.detectMultiScale(gray, scaleFactor=1.1, minNeighbors=5)
print(f"Found {len(faces)} face(s)")

for (x, y, w, h) in faces:
    cv2.rectangle(frame, (x, y), (x + w, y + h), (0, 255, 0), 2)   # draw a green box

cv2.imwrite("entrance_camera_marked.jpg", frame)
OpenCV vs. deep learning

OpenCV's classic tools are fast and need no training — great for simple, controlled scenes. For harder problems (spotting a PPE violation in a crowded warehouse), you pair OpenCV's frame-handling with a trained deep learning model like a CNN.

Convolutional Neural Networks (CNN)

A CNN is a neural network specially built for images. Instead of looking at the whole picture at once, it slides a small window across it, hunting for simple patterns everywhere.

imagine this

Imagine checking a huge wall for cracks using a small flashlight, sweeping it across every inch in a grid pattern. That sweeping flashlight is a filter (or kernel) — a tiny grid of numbers that lights up when it finds a pattern it recognizes, like a vertical edge.

A CNN's layers, top to bottom

  1. Convolution layer. Slide filters across the image to produce "feature maps" — highlighting edges, textures, colors.
  2. Activation (ReLU). Keep only the positive signals; this lets the network learn non-straight-line patterns.
  3. Pooling layer. Shrink the feature map by keeping only the strongest signal in each small region — this saves computation and adds tolerance to small shifts.
  4. Repeat. Stack many convolution + pooling pairs so early layers see edges, middle layers see shapes, and deep layers see whole objects.
  5. Fully connected layer. Flatten everything and make the final decision — "cat", "dog", "person", "vehicle".

The code: a small CNN with Keras

build_cnn.py
from tensorflow.keras import layers, Sequential

model = Sequential([
    layers.Conv2D(32, (3,3), activation="relu", input_shape=(128,128,3)),  # find simple patterns
    layers.MaxPooling2D((2,2)),                                                  # shrink by keeping strongest signal

    layers.Conv2D(64, (3,3), activation="relu"),                              # find bigger patterns
    layers.MaxPooling2D((2,2)),

    layers.Flatten(),                                                          # turn the grid into one long list
    layers.Dense(64, activation="relu"),
    layers.Dense(1, activation="sigmoid"),                                            # helmet vs. no helmet
])

model.compile(optimizer="adam", loss="binary_crossentropy", metrics=["accuracy"])
model.summary()
Why this matters for surveillance

Spotting a hard hat, an unattended bag, or an unauthorized vehicle in a busy camera feed is exactly this kind of pattern-in-an-image problem — CNNs are the core engine behind most video analytics, including Scanalitix's PPE compliance and ANPR features.

Transfer learning

Instead of teaching a network to see from zero, transfer learning starts with a network that already learned to see from millions of photos — and just teaches it your specific task.

imagine this

You wouldn't teach a fluent English speaker the alphabet before teaching them Spanish — you'd build on what they already know: letters, grammar, how language works. Transfer learning does the same thing: it reuses a network's existing knowledge of edges, shapes, and textures, and only retrains the final part for your new task.

Why not just train from scratch every time?

Training from scratchTransfer learning
Data neededOften 100,000+ labeled imagesCan work with a few hundred to a few thousand
Training timeDays to weeks on powerful GPUsOften hours, sometimes minutes
Starting knowledgeNone — learns edges and shapes from zeroAlready knows edges, shapes, textures

Try it yourself: freeze vs. retrain

A pretrained network has early layers (general shapes) and late layers (task-specific decisions). Choose which layers stay "frozen" (locked, reused as-is) and which get retrained on your new, small dataset of warehouse forklifts.

  • Layer 1 — edges & colors
  • Layer 2 — textures & corners
  • Layer 3 — shapes & parts
  • Layer 4 — object-specific features
  • Output layer — final decision

    • Layers 1–3 frozen (reused as-is), layers 4–5 retrained on your forklift photos.

    The code: fine-tuning a pretrained model

    transfer_learning.py
    from tensorflow.keras.applications import MobileNetV2
from tensorflow.keras import layers, Model

# Load a model already trained on 1.4 million general images
base = MobileNetV2(weights="imagenet", include_top=False, input_shape=(224,224,3))

base.trainable = False   # freeze it — keep its existing knowledge untouched

# Add our own small "head" for the new task: forklift vs. no forklift
x = layers.GlobalAveragePooling2D()(base.output)
x = layers.Dense(64, activation="relu")(x)
output = layers.Dense(1, activation="sigmoid")(x)

model = Model(inputs=base.input, outputs=output)
model.compile(optimizer="adam", loss="binary_crossentropy", metrics=["accuracy"])

# Only the new head trains — on just a few hundred warehouse photos
model.fit(warehouse_images, warehouse_labels, epochs=10)

    When a surveillance platform expands into a new industry — say, from retail into e-courts — transfer learning lets the vision models adapt to new camera angles and objects fast, without needing millions of fresh labeled images first.

    YOLO & edge device AI

    YOLO is the algorithm that made real-time object detection possible. Edge AI is running that detection directly on the camera or a nearby box — not in a distant data center — so the answer comes back in milliseconds.

    imagine this

    Older detectors worked like a security guard who first circles the whole room marking "something might be here" spots, then walks back to examine each one closely — slow, two trips. YOLO is a guard who glances at the entire room once and immediately calls out everything they saw and where — "person, front door; car, driveway" — in one look. That's why it's named You Only Look Once.

    How YOLO sees a scene

    1. Split the image into a grid. Say, 13×13 cells laid over the whole frame.
    2. Each cell makes a guess. "Is the center of an object sitting inside me? If so, what box would contain it, and how confident am I?"
    3. Every cell predicts several boxes at once. All cells do this in parallel, in a single pass through the network — not one-by-one.
    4. Classify each box. The network also outputs class probabilities — person, car, helmet, bag — for every candidate box.
    5. Clean up overlaps. A step called Non-Max Suppression throws away duplicate boxes around the same object, keeping only the most confident one.

    Two-stage detectors vs. YOLO

    Two-stage (e.g. Faster R-CNN)YOLO (single-stage)
    Passes through the networkTwo — propose regions, then classify themOne — boxes and classes together
    SpeedSlower — a few frames per secondFast — real-time video, 30-100+ FPS
    Best forCases needing the highest possible precisionLive video: cameras, drones, vehicles

    run_yolo.py
    from ultralytics import YOLO

# "n" = nano — the smallest, fastest version, built for edge devices
model = YOLO("yolov8n.pt")

results = model("warehouse_camera.jpg")

for box in results[0].boxes:
    label = model.names[int(box.cls)]

model.export(format="engine")              # TensorRT, for an NVIDIA Jetson

    BandwidthEvery camera streams full video upstream, constantlyOnly alerts/clips need to be sent, not raw video
    PrivacyRaw footage leaves the siteSensitive video can stay on-site entirely
    Compute availablePractically unlimitedLimited — small chip, limited power/heat budget
    The catch: edge hardware is small

    A camera or a drone can't fit a server-room GPU. So the model has to be shrunk first — this is exactly the model optimization lesson (quantization, pruning, distillation) applied specifically so a detector can run on a chip the size of a coin.

    Nano & edge-friendly models

    YOLO-Nano / YOLOv8n / YOLO11n

    The smallest official YOLO variants — a fraction of the parameters of the full-size model, tuned to run in real time on small chips.

    MobileNet / MobileNetV3

    Built from the ground up for phones, using "depthwise separable" convolutions that need far less computation than normal ones.

    EfficientNet-Lite / SqueezeNet

    Squeeze strong accuracy out of very few parameters — designed to fit in tight memory budgets.

    NanoDet / TFLite Micro models

    Detection models small enough (often under 5MB) to run on microcontrollers with no operating system at all.

    Where these nano models actually run

    NVIDIA Jetson Nano / Orin Nano

    A credit-card-sized computer with its own small GPU, built specifically to run vision models at the edge.

    Google Coral Edge TPU

    A tiny dedicated chip that only does one thing — run quantized neural networks — extremely fast and low-power.

    Smartphone NPUs

    Most modern phones have a built-in Neural Processing Unit just for running models like these without draining the battery.

    Camera-embedded chips

    Some IP cameras now ship with a small AI chip built right into the camera body itself.

    Processing tricks that make edge AI work

    • INT8 quantization — store weights as small 8-bit numbers instead of 32-bit, often a 4× size cut for barely any accuracy loss.
    • Lower input resolution — feeding the model a smaller frame (say 320×320 instead of 1280×1280) trades a little accuracy for a lot of speed.
    • Frame skipping — not every single video frame needs full detection; skipping frames intelligently saves power without missing events.
    • Hardware-specific compilation — converting a model to the exact format its chip prefers (TensorRT for Jetson, Core ML for iPhone, Edge TPU format for Coral).
    • Edge-cloud hybrid — the edge device makes the fast first call ("something moved"), then optionally sends just that clip to the cloud for a deeper, slower check.
    Real-time isn't automatic

    A model that hits 99% accuracy in a lab can still fail a real deployment if it can't process frames fast enough to keep up with live video — a slow model effectively "misses" fast-moving objects between the frames it manages to process.

    Straight back to Scanalitix

    This is exactly what powers Scanalitix's edge AI: nano detection models, quantized and compiled for the hardware sitting on-site, running ANPR, PPE compliance, and crowd analytics directly on the camera or a local box — so an alert fires in real time, even if the internet link to a central office briefly drops.

    TensorFlow

    TensorFlow is a free library from Google for building and running neural networks — from a research laptop all the way to a phone or a warehouse camera.

    imagine this

    A "tensor" is just a fancy word for a grid of numbers — a single number is a tensor, a list is a tensor, an image (a grid of pixel grids) is a tensor. TensorFlow's whole job is moving and transforming these grids of numbers, fast, on whatever hardware you give it — laptop, server, or phone.

    What TensorFlow is good at

    Production & scale

    Strong tools for serving models to millions of users reliably (TensorFlow Serving).

    Mobile & edge

    TensorFlow Lite runs optimized models directly on phones and small edge devices.

    Visualization

    TensorBoard lets you watch training progress live with graphs and charts.

    End-to-end pipelines

    TFX handles the whole journey from raw data to a monitored production model.

    The code: tensors, the basic building block

    tensors_101.py
    import tensorflow as tf

# A tensor is just a grid of numbers of any size
scalar = tf.constant(7)                          # a single number
vector = tf.constant([1, 2, 3])                # a list
image  = tf.zeros([128, 128, 3])              # height x width x color-channels

print("shape:", image.shape)                 # (128, 128, 3)

# TensorFlow automatically tracks operations so it can compute gradients
x = tf.Variable(3.0)
with tf.GradientTape() as tape:
    y = x ** 2                                   # y = x^2
slope = tape.gradient(y, x)
print("dy/dx at x=3:", slope.numpy())          # 6.0 — the exact slope of x^2 at x=3

    The code: training with TensorFlow directly

    train_tf.py
    import tensorflow as tf

(train_images, train_labels), (test_images, test_labels) = tf.keras.datasets.mnist.load_data()
train_images = train_images / 255.0   # scale pixel values from 0-255 down to 0-1

model = tf.keras.Sequential([
    tf.keras.layers.Flatten(input_shape=(28, 28)),
    tf.keras.layers.Dense(128, activation="relu"),
    tf.keras.layers.Dense(10, activation="softmax"),   # 10 digits: 0-9
])

model.compile(optimizer="adam", loss="sparse_categorical_crossentropy", metrics=["accuracy"])
model.fit(train_images, train_labels, epochs=5)
model.evaluate(test_images, test_labels)
    TensorFlow and Keras

    Keras (see the Keras lesson) is now built directly into TensorFlow as its official easy-mode interface — most engineers write tf.keras... exactly like the code above.

    PyTorch

    PyTorch is Meta's (Facebook's) free deep learning library. It's the favorite of most researchers because it feels like writing regular Python — you build the network step by step, and can inspect any value at any point.

    imagine this

    TensorFlow's older style was like writing a recipe entirely in advance, then handing it to a chef who cooks it all at once. PyTorch is more like cooking live — you taste and adjust each step as it happens. This "define-as-you-go" style is called a dynamic computation graph, and it makes debugging much easier.

    TensorFlow vs. PyTorch, honestly

    TensorFlowPyTorch
    Feels likeAn industrial production systemRegular, flexible Python
    Most popular inLarge-scale production, mobile/edgeResearch, rapid experimentation
    DebuggingImproved a lot with eager modeVery easy — step through like normal code
    TodayBoth are strong, production-ready choices — many teams use either, or both

    The code: a network in PyTorch

    train_pytorch.py
    import torch
import torch.nn as nn

# Define the network as a Python class — very explicit, very flexible
class SpamDetector(nn.Module):
    def __init__(self):
        super().__init__()
        self.layer1 = nn.Linear(2, 8)     # 2 inputs -> 8 hidden neurons
        self.layer2 = nn.Linear(8, 1)     # 8 hidden neurons -> 1 output
        self.relu   = nn.ReLU()
        self.sig    = nn.Sigmoid()

    def forward(self, x):
        x = self.relu(self.layer1(x))
        return self.sig(self.layer2(x))

model     = SpamDetector()
loss_fn   = nn.BCELoss()
optimizer = torch.optim.Adam(model.parameters(), lr=0.01)

# The training loop — you can see and control every single step
for epoch in range(100):
    predictions = model(training_inputs)
    loss = loss_fn(predictions, training_labels)

    optimizer.zero_grad()   # clear old gradients
    loss.backward()         # compute new gradients (backpropagation)
    optimizer.step()        # nudge the weights
    Word check

    Gradient = the direction and size of the nudge that would reduce loss. PyTorch calculates this automatically with a feature literally called autograd.

    Keras

    Keras is the friendly front door to deep learning. It sits on top of TensorFlow and lets you describe a whole neural network in a handful of readable lines.

    imagine this

    If TensorFlow is a fully equipped professional kitchen, Keras is the labeled, pre-measured recipe kit: "add this layer, then this layer, then bake." You get the same powerful oven underneath, but with far less setup to write yourself.

    Two ways to build a model in Keras

    Sequential

    A simple stack of layers, one after another — perfect for most straightforward models.

    Functional

    Layers connected however you like — needed for models with multiple inputs, outputs, or branching paths.

    The code: Sequential API

    keras_sequential.py
    from tensorflow import keras
from tensorflow.keras import layers

model = keras.Sequential([
    layers.Dense(16, activation="relu", input_shape=(4,)),
    layers.Dense(16, activation="relu"),
    layers.Dense(3,  activation="softmax"),   # 3 possible categories
])

model.compile(
    optimizer="adam",
    loss="sparse_categorical_crossentropy",
    metrics=["accuracy"],
)

history = model.fit(X_train, y_train, epochs=20, validation_split=0.2)
model.save("my_first_model.keras")   # one line to save the whole trained model

    The code: Functional API for a branching model

    Useful when a model needs two inputs — for example, combining a camera image with a sensor reading.

    keras_functional.py
    from tensorflow.keras import layers, Model, Input

image_in  = Input(shape=(64,64,3), name="camera_frame")
sensor_in = Input(shape=(5,),      name="sensor_readings")

x = layers.Conv2D(16, 3, activation="relu")(image_in)
x = layers.GlobalAveragePooling2D()(x)

combined = layers.concatenate([x, sensor_in])   # merge the two branches
output = layers.Dense(1, activation="sigmoid")(combined)

model = Model(inputs=[image_in, sensor_in], outputs=output)
    Which library should a beginner pick?

    Start with Keras — it teaches the concepts fastest. Once ideas like layers, loss, and epochs feel natural, PyTorch and raw TensorFlow become much easier to read.
